# Builder Handoff Template

Use this checklist when handing a completed weekly package to Anthony for dashboard implementation.

## Required weekly package

- [ ] Course content / lesson
- [ ] 5–8 key terms with clear definitions
- [ ] Exact student dashboard build for the week
- [ ] Student directions written directly to students
- [ ] Example / model of completed work
- [ ] Submission requirements
- [ ] Rubric or answer key
- [ ] Quiz, test, or discussion materials when assigned
- [ ] Dashboard needs: what the main class dashboard must contain to support the week

## Alignment check

Before handoff, review the week before and after yours.

- [ ] Does this build on prior learning?
- [ ] Does it prepare students for the next section?
- [ ] Does it avoid unnecessary duplication?
- [ ] Are terms and instructions consistent with the rest of the course?
- [ ] Does the dashboard component fit the student's evolving AI Management Dashboard?
- [ ] Are assessment questions aligned to the material actually taught?

## Review workflow

1. Builder completes the package.
2. A second builder reviews clarity, duplication, and alignment.
3. Daniel reviews content, workload, grading, and undergraduate management focus.
4. Anthony implements approved material in the class dashboard / GitHub.
5. A different team member tests the page as an undergraduate student.
6. Required changes are made before the work is merged into the main version.

## Handoff note

When sending the package, identify:

- Week number
- Builder name
- Dashboard component being added/changed
- Assessment type, if any
- Any dependencies on earlier weeks
- Any links/resources that must appear on the class dashboard
- Any technical behavior the student needs to demonstrate

Do not send confidential student information, credentials, API keys, or other secrets through the repository.
